关于计算模型 GTO Trainer 是 GTO 风格的练习工具：它近似 solver 的策略，而不是运行完整的求解器，接近的局面请当作参考而非定论。翻前：近似 solver 范围表（含混合频率）；推/弃与面对全下按真实 EV 计算；ICM 用 Malmuth-Harville 模型。翻后：蒙特卡洛模拟，对手针对你的范围行动——会加注/过牌加注、用听牌诈唬、按牌面选尺度，范围每条街收窄；支持 3-bet/4-bet 与 3 人底池。EV 差距在误差带内的选项都算正确。是练习近似，非完整求解器。

帮助

练习模式（左侧文件）

  • FullHand 完整牌局：从翻前打到河牌，每个决策都评分。
  • Preflop 翻前练习：开池、面对加注、面对 3-bet、推/弃等翻前局面快速刷题。
  • Postflop 翻后练习：直接从翻牌开始；配合左下「练习筛选」只练特定局面（例如：翻牌 · 面对下注 · 中对）。
  • Review 错题本：最近的决策记录，可以「重做」失误。Stats 统计：按街、局面、牌力、位置查看准确率和最弱项。

怎么评分

  • 每个选项都计算 EV（相对于弃牌的期望筹码收益，单位 bb）。EV 最高的是最佳；与最佳相差在模拟误差内的选项标「≈最佳」，同样算对。
  • 评分：最佳 良好 不精确 严重失误，按 EV 损失占底池的比例划分。翻前范围题按 solver 频率评分。
  • 状态栏的小图标是最近的决策：● 最佳 ◐ 良好 ▲ 不精确 ✕ 严重失误。

 9@Service

12    private final OrderRepository orderRepository;

15    public OrderService(OrderRepository orderRepository, PaymentClient paymentClient) {
16        this.orderRepository = orderRepository;

20    @Transactional
21    public Order placeOrder(CreateOrderRequest request) {
22        BigDecimal total = request.items().stream()
23                .map(item -> item.price().multiply(BigDecimal.valueOf(item.quantity())))
24                .reduce(BigDecimal.ZERO, BigDecimal::add);
25
26        if (total.compareTo(BigDecimal.ZERO) <= 0) {
27            throw new IllegalArgumentException("Order total must be positive");
28        }
29
30        Order order = Order.create(request.customerId(), request.items(), total);
31        orderRepository.save(order);
32
33        PaymentResult result = paymentClient.charge(order.id(), total);
34        if (!result.success()) {
35            order.markFailed(result.reason());
36            return order;
37        }
38
39        order.markPaid(result.transactionId());
40        return order;
41    }
42
43    public List<Order> findRecent(String customerId, int limit) {
44        // TODO: move paging to repository layer
45        return orderRepository.findByCustomerIdOrderByCreatedAtDesc(customerId)
46                .stream()
47                .limit(limit)
48                .toList();
